# 0.3.1 候选版：外放回声处理

状态：随 0.3.1 Beta 提供，程序内部仍标识为 `0.3.1-candidate`，以保留
候选配置和启动行为。真实语音的外放与打断验收尚未全面完成；旧的
0.3.0 Beta 可在 GitHub Releases 下载用于回退。

## 做了什么

- Fish 播放、物理麦克风和播放参考由同一个双工回调管理。
- 测量实际声学延迟，补偿声卡时间信息不可靠的情况。
- 线性自适应回声滤波 + WebRTC 残余回声处理；不关闭麦克风。
- 独立语音检测停止自己的播放，旧音频按 epoch 丢弃。
- 有界播放队列异步等待，打断不必等待排队结束。
- 网页收音轨道保持不变，组件故障时切回已开启的真实麦克风。
- 字幕、逗号断句、免费 Fish 模型和两套 Codex 文本采集逻辑保留。

## 前提与使用

仅 Windows x64。需要另外安装官方 VB-CABLE 驱动；项目不捆绑驱动、
不改 Windows 默认设备。候选设置中的设备下拉框选择真实麦克风和扬声器，
勾选“外放回声处理”。应用与 0.3.1 扩展一起使用，并重新开始网页语音。

浏览器会把处理后的 CABLE Output 接入现有语音。Codex 桌面语音的设备
选择不能由网页扩展接管；桌面外放 AEC 需要单独验证其虚拟输入设备设置，
不能把网页测试当作两套桌面版的验收。

### 桌面输入链路（本轮修复）

回声组件启动不等于 Codex 正在使用它的输出。客户端现在读取 Windows
Capture 端点上的活动 ChatGPT 音频会话，核验实际输入是否为
`CABLE Output (VB-Audio Virtual Cable)`，不采集系统音频、不修改默认设备。
两个 Codex 有任何活动输入仍在实体麦克风、没有活动输入或枚举失败，
均不能宣布桌面 AEC 就绪。诊断输出 `desktopEchoRoute` 和
`desktopReplacementPaused` 区分这些状态。

开启 AEC 后，未接通的桌面回复仍有字幕，但不接管 Fish 或静音原声；
使用途中虚拟路由失效则取消旧播放。恢复路由后须开始新的回复，避免
续读旧回复的半截或重复朗读。网页接入和已关闭 AEC 的现有行为保留。
候选启动入口现在也传入 `--desktop`，避免桌面采集被遗漏。

虚拟输入选择仍需在客户端支持的设备设置中完成；代码没有伪造或绕过
Codex 的输入设置。若客户端只能使用系统默认输入，则需明确处理默认
输入的选择及退出恢复后，才能宣称自动接入。当前不自动改系统默认。

参考：[AEC Client](https://github.com/samudinzul/aec-client) 的虚拟麦克风
输出及客户端输入选择；[pywebrtc-audio](https://github.com/strands-labs/pywebrtc-audio)
的播放参考处理。AEC Client 使用系统播放参考，本项目仅使用自己的 Fish PCM。

网页部署故障另行诊断：客户端记录配对成功、配对拒绝和认证失败次数，
不记录 token；扩展弹窗显示自身版本并区分无法连接、配对拒绝和认证失败。
重载扩展不等于通过验收，仍须看到真实网页心跳及新回复文本。

`--candidate` 使用单独的 `.voicebridge-next-candidate` 配置目录。
同一时间只能运行一个 VoiceBridge，避免抢播放和桥接端口。

## 测试记录：2026-10-03

2026-10-09 补充：固定免费模型的本地三段文本检查中，96 字均已提交，
播放队列接受音频后排空，维护者确认首、中、末段全部听到且只读一次。
这项结果验证文本到 Fish 播放链路，不代替网页及两套 Codex 的真实采集，
也不证明所有扬声器环境的回声消除或真人打断。

- 原有离线回归通过：逗号分段、去重、字幕、会话隔离、免费模型锁定、
  故障恢复、桥接权限；新增背压等待与立即取消检查。
- 新增网页检查：组件迟到、断开、重连、心跳过期、虚拟输入失败、
  AudioContext 未启动时保持真实麦克风，停止后释放音频资源。
- 合成信号检查：回声抑制、同时说话的近端保留、冷启动回声不误打断、
  近端语音清空旧播放队列。合成分数不等于真实外放效果。
- 维护者内置扬声器：初始声卡时间路径不足，测到的抑制约 0 dB；
  自动延迟估计得到约 166.5 ms，校准噪声测试得到约 3.3 dB。
  环境声音也计入该指标，不能据此宣称解决自问自答。
- 已用固定免费模型生成一段本地测试参考语音，没有上传麦克风音频。
  早期候选发生一次误打断；检测已调整，安静外放复测及真人打断待完成。
- 实机回调 p95 约 2.3 ms / 10 ms 帧。最终候选含新增检测，需重新测量。
- 本轮使用已保存的 Fish 测试语音，在内置麦克风/扬声器复测：尾段原始
  与处理后麦克风能量比约 9.22 dB，回调 p95 约 3.93 ms，声学延迟约
  178 ms；无输入溢出、输出欠载或误触发播放打断。该能量比包含环境
  声，不能当作严格 ERLE，也不证明真人同时讲话或 Codex 输入已通过。
- 桌面新增 14 项离线检查：实际输入路由、两客户端混合输入、路由失效、
  恢复不复读；使用真实文本管线验证字幕保留及网页继续换声。实机
  Capture 会话枚举成功；无语音时正确显示等待麦克风，而非宣称就绪。
- 浏览器控制连接仍返回 nodeRepl.fetch request failed，不能自动完成网页验收。

## 发布门槛

### 桌面原声与换声重复播放修复

原来原声静音依赖文本路由的 start，该事件会等到首个助手文本才转发；
桌面 UI 的轮次变化又会发 interrupt，导致原声反复恢复。本轮静音改为
在语音 UI 激活且换声/输入路由可用时提前接管，并跨正常轮次打断保持。
语音结束、TTS 不可用或路由不安全时恢复原状态。播放会话按设备与实例
分别保存状态，覆盖所有输出设备与后创建的会话，不触碰麦克风或 Fish。
检测间隔 100 ms；尚不能保证新输出会话的开头绝对没有漏音，需真人测试。

新增正常退出接口仅允许已认证且无浏览器 Origin 的本机启动器，方便
后续更新，无强制终止。浏览器扩展即使持有桥接令牌也不能调用退出。
桌面静音回归与权限检查已通过，真实输出静音与用户听感待替换后验证。

安静时连续播放三轮，不产生助手内容的用户转写；朗读中说话确实能
打断并被网页转写；组件被关闭后仍能讲话；重启后不复读；30 分钟
连续语音没有断流。两套 Codex 和第二台 Windows 电脑另外验收。

## 构建

Python 3.12：`scripts/BuildAec.ps1 -Python python`。
随后 `scripts/Package.ps1 -IncludeAec`，运行 `scripts/VerifyPackage.ps1`。
普通离线检查不会读取真实密钥或调用 Fish。`aec/probe.py` 是显式选择
扬声器后运行的本地测量工具，只保留指标，不保存麦克风录音。
