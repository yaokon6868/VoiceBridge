# 使用场景与支持范围

[返回首页](../README.md) · [详细安装与使用](USER_GUIDE.md)

VoiceBridge 当前的核心是 **助手文字 → 实时字幕 + 指定音色朗读**。它适合已经使用 ChatGPT Voice、希望改变回答声音并同时看见文字的 Windows 用户。它不会替你提供 ChatGPT 账号，也不是一个独立聊天模型。

## 支持范围一览

| 场景 | 当前状态 | 使用前提与边界 |
|---|---|---|
| Chrome 上的 ChatGPT Voice 助手回答 | 0.3.1 Beta 核心体验 | 程序、同包扩展、Fish 配置接通；本轮播放完整性已有本机验证，真实网页长回复仍需单独测试 |
| 回答的实时悬浮字幕 | 已实现，依赖文字来源接通 | 显示助手回复，不是任意音频字幕，也不包含独立的麦克风识别器 |
| 普通版 Codex 桌面语音 | Beta 兼容性功能 | 0.3.1 按监听设置启动，也可托盘接入；界面有可访问回复文字，需独立验证 |
| 隔离版 Codex 桌面语音 | Beta 兼容性功能 | 与普通版分别测试，不因网页已接通就视为桌面成功 |
| 扬声器外放并随时说话打断 | 0.3.1 可选实验功能 | 需要 AEC、另装虚拟音频驱动及正确路由；外放回声与真人打断尚未全面验收 |
| ChatGPT 普通文字聊天、任意旧回复朗读 | 未列入已验证支持 | 不要把 Voice 采集自动等同于所有文字消息采集 |
| 微信、QQ 消息或通话换声 | 尚未接入 | 需要新增对应文字或音频来源适配 |
| B站视频、直播换声或实时翻译 | 尚未接入 | 还需字幕/音频来源、背景声处理、同步等能力 |
| PDF、文章、剪贴板与任意选中文字朗读 | 尚未提供通用入口 | 属于后续文本来源扩展方向 |
| 把用户麦克风直接变成另一种音色 | 未实现 | 需要语音到语音转换引擎和输出路由；当前 TTS 不是该功能 |
| 手机小程序、macOS、Linux | 未提供 | 当前发布包针对 Windows x64 |

“Beta”表示可以参与体验和验证，不表示所有版本、设备及长时间使用都已可靠。

## 场景一：用喜欢的声音与 ChatGPT 聊天

**适合**：日常讨论、头脑风暴、闲聊，希望回答更符合个人听感。

示例提问：“帮我想三个周末活动，分别说说适合什么情况。”

使用流程：

1. 在 Fish 音色页试听并复制模型 ID，保存到 VoiceBridge。
2. 开启 ChatGPT Voice，正常说话提问。
3. 看字幕更新，同时听 Fish 逐步朗读助手回复。
4. 想换音色时修改 Voice / Reference ID 并保存，用一轮新回答验证。

你的声音由 ChatGPT 接收。VoiceBridge 改变的是助手回答的朗读声音，不会克隆你的声音，也不会把你的说话声音转换后发送给其他人。

## 场景二：听回复，同时核对文字

**适合**：容易漏听术语、人名或步骤，或者希望把回答保留在视线内。

示例提问：“分三步解释如何整理今天的工作计划。”

使用流程：调整字幕到屏幕边缘，设置足够清晰的字号和文字不透明度，将背景调低，再开启鼠标穿透。助手文字增量到达时更新字幕，朗读按短语缓冲。

字幕与 Fish 播放不是精确逐字卡拉 OK 同步；字幕可能先于声音显示。当前没有字幕文件导出、长篇记录整理或独立的无障碍兼容性认证。

## 场景三：语言练习与学习问答

**适合**：通过对话提问、听解释，再用字幕核对助手的原话。

示例提问：“我们练习一段英语点餐对话，每次只回复一两句。”

使用流程：让 ChatGPT 使用目标语言，选一个适合该语言的 Fish 音色，观察文字与声音是否一致。遇到专有词或长段落时，可以要求 ChatGPT 分段或简短回答。

ChatGPT 的内容能力和 Fish 的语音语言表现分别由对应服务决定。VoiceBridge 没有独立的发音评分、教学课程、字幕翻译或双语对照功能。

## 场景四：开发时听 Codex 的语音回复

**适合**：看代码或操作其他窗口时，希望听见 Codex 语音回复，并通过悬浮字幕核对重点。

示例提问：“简短解释这个修改的目的，以及下一步要验证什么。”

使用流程：按 [桌面接入步骤](USER_GUIDE.md#7-普通版与隔离版-codex) 开启监听，先单独测试普通版，再测试隔离版。检查是否收到完整的新回复，是否只有选定的 Fish 声音，以及中途打断后旧播放是否停止。

桌面采集依赖客户端界面暴露的文字，客户端更新可能影响识别。工具状态、思考提示或回复重绘不应被当作新的回答；若出现漏读、复读或双声，应按具体入口反馈，不能以另一入口通过来判断整体成功。

## 场景五：电脑扬声器外放

**适合**：希望不戴耳机，并保留朗读期间随时开口打断。

这是 0.3.1 Beta 的实验验证场景，首次体验仍建议耳机。0.3.0 不含处理器，Fish 声音来自独立播放器，不能假设 ChatGPT 原有的回声处理会消除它；扬声器的声音可能被麦克风听到，变成“用户重复助手的话”。

候选架构使用自己的 Fish 播放音频作为参考，处理真实麦克风输入，再把处理后的声音交给客户端。组件运行、虚拟线缆有声音、网页/桌面实际选中了处理后的输入，是三个需要分别核对的环节。

操作与验收见 [实验 AEC 步骤](USER_GUIDE.md#10-031-beta-实验-aec) 和 [AEC 技术说明](AEC-031.md)。不能用暂停收音的办法代替“随时语音打断”的目标，也不能把一次安静外放成功当作所有设备和音量都通过。

## 后续扩展：稳定核心，逐个接入来源

未来希望保留统一的字幕、断句、播放、去重、打断和故障恢复，再增加来源适配。下面是方向，不是已交付功能或发布日期承诺：

| 方向 | 可能的接入路线 | 还需要解决什么 |
|---|---|---|
| 更多 AI 网页或应用 | 官方文本接口、网页事件或可访问文字 | 权限、增量/最终状态、页面变化、原声抑制 |
| 微信、QQ 文字 | 用户选择/复制的内容，或针对应用的文字适配 | 消息边界、隐私、重复检测、稳定读取 |
| 文章、文档朗读 | 文本输入、文件导入、选中文字入口 | 清洗格式、段落导航、长任务暂停与恢复 |
| 视频内容换声 | 优先字幕；无字幕再考虑识别音频 | 原声处理、视频同步、背景音乐、多说话人 |
| 实时语音直接换声 | 语音转换引擎、指定应用音频来源、虚拟输出 | 算力、端到端延迟、原语气保留、回声及同步 |

文本重新朗读、音频识别后重新朗读、音频直接转换音色是不同链路。后两者不能仅靠更换 Fish Voice ID 自动完成。

欢迎在 [Issues](https://github.com/yaokon6868/VoiceBridge/issues) 提交具体场景：想接哪个应用、内容来自文字还是音频、希望在本机听还是发送给别人、是否必须实时打断。可复现的使用需求比“支持所有软件”更方便评估和实现。
